# 膝点配置档与自适应并发

GuideLLM 的 `knee` 配置档用于估算并发量增加时输出吞吐量不再显著增长的位置。这个转折点称为吞吐量拐点。配置档会先运行一组初始并发点并报告拐点；你也可以选择在拐点附近增加测试点，以细化估算结果。

使用 `--profile` 配置 `kind=knee`，并提供 `initial_streams` 列表，或同时提供 `min_streams`、`max_streams` 和 `count`，即可启用拐点检测。默认情况下不会进行自适应细化。

## 基本用法

测量指定的一组并发点并报告拐点：

```bash
guidellm run \
  --backend kind=openai_http,target=http://localhost:8000 \
  --profile '{"kind":"knee","initial_streams":[1,5,10,20,40,80,160]}' \
  --data kind=synthetic_text,prompt_tokens=1000,output_tokens=1000 \
  --constraint kind=max_duration,seconds=60 \
  --output kind=json,path=knee-benchmark.json
```

要自动运行额外的并发点，请在同一个配置档中设置自适应选项：

```bash
--profile '{"kind":"knee","initial_streams":[1,5,10,20,40,80,160],"adaptive":true,"points_each_side":5,"max_step":3}'
```

如果要生成间距均匀的初始点，请改为提供包含端点的范围和点数：

```bash
--profile '{"kind":"knee","min_streams":1,"max_streams":9,"count":5}'
```

此示例会运行并发点 `1, 3, 5, 7, 9`。生成的点会四舍五入到最接近的整数，恰好位于中间时向上取整。范围内必须包含足够多的整数，才能生成所需数量的不同点。如果需要精确指定不等间距的值，请使用 `initial_streams`。

`knee` 配置档使用并发调度策略，并要求至少提供五个按升序排列、互不相同的正整数并发点。拟合拐点至少需要五个已完成且测得输出吞吐量的并发点。选择的范围应覆盖吞吐量上升阶段和平台阶段；如果曲线较平或近似线性，结果将为 `status: no_knee`。

## 配置

| 选项               | 默认值  | 说明                                         |
| ------------------ | ------- | -------------------------------------------- |
| `initial_streams`  | —       | 精确指定初始并发点，至少五个，并按升序排列。 |
| `min_streams`      | —       | 生成的初始并发点下限，包含该值。             |
| `max_streams`      | —       | 生成的初始并发点上限，包含该值。             |
| `count`            | —       | 生成的点数，至少为五。                       |
| `adaptive`         | `false` | 在初始饱和估算值附近运行额外的并发点。       |
| `points_each_side` | `5`     | 自适应锚点上下方各自选择的网格点数上限。     |
| `max_step`         | `5`     | 自适应并发网格所考虑的最大整数间距。         |

在 `knee` 配置档中，设置 `initial_streams`，或同时设置 `min_streams`、`max_streams` 和 `count`。这两种形式都会作为一次基准测试运行。`points_each_side` 和 `max_step` 必须是正整数。所有自适应并发值也必须是正整数。开始自适应细化前，GuideLLM 会移除已经测量过的并发点。标准配置档的计时选项（`rampup_duration`、`warmup` 和 `cooldown`）会同时应用于两个阶段。

## 拐点的计算方式

GuideLLM 将每秒成功输出 token 数作为吞吐量，并将并发量作为负载。分析步骤如下：

1. 按并发量排序测量结果，并忽略没有吞吐量数据的测量值。独立的拟合函数会对重复并发量的测量结果取平均；但 `knee` 配置档要求并发点互不相同，因为重复点可能导致饱和检测器的判断不明确。
2. 将并发量和吞吐量归一化到可比较的尺度。
3. 为完整的吞吐量曲线拟合一条直线。
4. 尝试符合条件的断点，并分别为每个断点之前的上升段和之后的尾段拟合直线。
5. 只有同时满足以下条件时才接受断点：上升段斜率为正；尾段斜率不超过上升段斜率的 25%；两段直线的拟合使平方误差至少减少 50%；断点处的吞吐量至少达到观测峰值的 85%。
6. 在符合条件的拟合结果中选择合并平方误差最低的一项，并将两条拟合直线的交点作为拐点。如果交点超出断点相邻的已测点范围，则使用断点本身。

虽然并发量是整数，拟合得到的交点仍可能是小数。GuideLLM 还会报告 `saturation_concurrency`（大于或等于拟合拐点的第一个已测整数并发量）和 `breakpoint_concurrency`（最佳分段拟合所使用的已测点）。

## 自适应细化

GuideLLM 会先分析初始基准测试结果，再选择自适应点。如果检测到吞吐量拐点，就以拟合出的拐点作为选择中心。如果没有检测到吞吐量拐点，但过饱和检测器找到了边界，GuideLLM 会使用最后一个安全并发量与第一个过饱和并发量的中点。如果边界之前没有安全点，则使用第一个过饱和并发量。如果两种方法都没有检测到饱和，或两者结果不一致，则跳过自适应细化。

自适应网格会使用不超过 `max_step` 的最大步长，同时确保所需的下方点为正数。选择中心会四舍五入到最接近该步长的倍数，作为整数锚点；恰好位于中间时向上取整。如果即使步长为 1 也无法容纳所有下方点，则会忽略非正候选值。锚点本身也是候选点，因此排除已测点之前，网格最多包含 `2 * points_each_side + 1` 个点。

例如，选择中心为 `19.97`，`points_each_side=5` 且 `max_step=3` 时，锚点为 `21`，候选网格如下：

```text
6, 9, 12, 15, 18, 21, 24, 27, 30, 33, 36
```

若要使用更密集的网格，请设置 `max_step=1`：选择中心为 `19.97` 时，锚点为 `20`，上下各取五个点后，候选值为 `15` 到 `25`。

初始点和自适应点使用相同的基准测试流程，包括相同的后端、数据加载器、配置档计时设置和约束。时长限制会分别应用于每个点，因此增加测试点会延长总运行时间。网格范围可以超出初始并发范围。任一阶段中，设置了 `stopping_scope: all` 的约束都会停止整个配置档。如果初始扫描期间触发该约束，将跳过自适应细化；如果细化期间触发，则不会运行剩余的计划点。

进度显示会为初始扫描以及最多 `2 * points_each_side + 1` 个自适应点预留空间。如果部分点被排除、跳过细化或触发了停止约束，配置档结束时的实际测量数量可能会更少。

额外测试点完成后，GuideLLM 会合并初始和自适应测量结果，并计算最终拐点。自适应选择只执行一次；最终拐点不会再触发新一轮细化。如果禁用了细化或跳过了细化，最终分析只使用初始测量结果。

## 使用过饱和检测

计算吞吐量拐点无需添加过饱和约束。添加该约束可以基于并发请求和首 token 时间提供独立的时序证据。收集初始曲线时，可使用 `mode=monitor` 记录检测元数据，同时继续运行其余并发点：

```bash
--constraint kind=over_saturation,mode=monitor,min_seconds=30
```

有关检测器的所有设置，请参阅[过饱和停止指南（英文）](../../guides/over_saturation_stopping.md)。

## 结果

控制台输出会汇总最终拐点和自适应细化状态。JSON 和 YAML 报告会将完整分析保存在标准配置档的 `conclusions` 列表中，条目类型为 `kind: knee_detection`。该条目包含：

- `initial`：基于配置的并发点进行的拐点和过饱和分析。
- `adaptive_plan`：选择中心、锚点、步长、候选点、排除点和计划运行的额外点。停止约束可能导致部分计划点未运行。
- `final`：对合并后的初始和自适应测量结果进行的分析。

初始和自适应基准测试的测量结果会一起保存在报告的 `benchmarks` 列表中，初始测量排在前面。通过这些测量结果可以查看实际运行过的点。配置保存在 `config.spec.profile` 中；每项基准测试也会记录其配置档和并发策略。
