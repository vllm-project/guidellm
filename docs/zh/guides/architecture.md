# 架构

GuideLLM 通过模拟真实场景中的推理工作负载，帮助评估和优化大语言模型（LLM）部署。其模块化架构兼具灵活性和可扩展性。下文概述核心组件及其交互方式。

```
+------------------+       +------------------+       +------------------+
|   DatasetCreator | --->  |   RequestLoader  | --->  |     Scheduler    |
+------------------+       +------------------+       +------------------+
                                                    /         |          \
                                                   /          |           \
                                                  /           |            \
                                                 v            v             v
                                       +------------------+ +------------------+
                                       | RequestsWorker   | | RequestsWorker   |
                                       +------------------+ +------------------+
                                                 |                     |
                                                 v                     v
                                       +------------------+ +------------------+
                                       |     Backend      | |     Backend      |
                                       +------------------+ +------------------+
                                                 |                     |
                                                 v                     v
                                       +---------------------------------------+
                                       |         BenchmarkAggregator           |
                                       +---------------------------------------+
                                                 |
                                                 v
                                       +------------------+
                                       |    Benchmarker   |
                                       +------------------+
```

## 核心组件

### 1. **Backend（后端）**

`Backend` 是与生成式 AI 后端交互的抽象接口，负责处理请求并生成结果。GuideLLM 支持将 vLLM 等兼容 OpenAI 的 HTTP 服务器用作后端。

- **职责：**
  - 接收来自 `RequestsWorker` 的请求。
  - 为文本补全或聊天补全请求生成响应。
  - 验证后端是否就绪，以及有哪些可用模型。

### 2. **RequestLoader（请求加载器）**

`RequestLoader` 从可迭代对象获取数据，并生成发送给后端的请求。它确保数据格式正确，可供后续处理。

- **职责：**
  - 从数据集或合成数据源加载数据。
  - 生成符合后端格式要求的请求。

### 3. **DatasetCreator（数据集创建器）**

`DatasetCreator` 负责加载数据源，并将其转换为 Hugging Face（HF）数据集条目，供 `RequestLoader` 流式读取。

- **职责：**
  - 从本地文件、Hugging Face 数据集或合成数据源加载数据。
  - 将数据转换为与 `RequestLoader` 兼容的格式。

### 4. **Scheduler（调度器）**

`Scheduler` 管理发送给后端的请求调度。它结合多进程、多线程和 asyncio，尽量减少开销并提高吞吐量。

- **职责：**
  - 调度发送给后端的请求。
  - 管理请求队列和结果队列。
  - 确保高效利用资源。

### 5. **RequestsWorker（请求工作进程）**

`RequestsWorker` 是一个工作进程：它从队列中取出请求，使用后端处理请求，再将结果返回给调度器。

- **职责：**
  - 处理调度器分配的请求。
  - 与后端交互以生成结果。
  - 将结果返回给调度器。

### 6. **Benchmarker（基准测试管理器）**

`Benchmarker` 封装对 `Scheduler` 的多次调用，每次调用对应一次基准测试。它使用 `BenchmarkAggregator` 汇总结果，并在完成后将其整理为 `Benchmark` 对象。

- **职责：**
  - 管理多次基准测试。
  - 汇总调度器返回的结果。
  - 将结果整理为最终的基准测试报告。

### 7. **BenchmarkAggregator（基准测试聚合器）**

`BenchmarkAggregator` 负责存储和整理基准测试结果。

- **职责：**
  - 汇总多次基准测试的结果。
  - 将结果整理为 `Benchmark` 对象。
