# v0.6.0 到 v0.7.2 CLI 迁移指南

## `guidellm benchmark [run]`

对生成式模型运行基准测试。

此命令现为 `guidellm run`

| v0.6.0 选项                                                                                                                                                                                                                                                                                                                                                                                                                              | v0.7.1 对应写法                                                                                                                                                                                                                           |
| :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| --backend-kwargs 用于传递给后端的参数 JSON 字符串。例如，'{"api_key": "apikey-\*", "verify": false}'                                                                                                                                                                                                                                                                                                                                     | 传入 `--backend` 构造函数的选项，例如 `--backend "kind=openai_http,api_key=sk…"`                                                                                                                                                          |
| --backend 后端类型。可选项：vllm_python、openai_http。                                                                                                                                                                                                                                                                                                                                                                                   | 后端配置中的 "kind"，例如 `--backend '{"kind": "vllm_python_async", "model": "gpt-4"}'`（`vllm_python` 是 `vllm_python_async` 的别名；批量推理使用 `vllm_python_batch`）                                                                  |
| --cooldown 冷却设置：int、float，或以字符串形式提供的 dict（json 或 key=value）。用于指定测量结束后等待的时间或请求数。数值在 (0, 1) 之间时表示时长或请求数量的百分比。数值 >=1 时表示秒数或请求数。高级配置请参阅 TransientPhaseConfig schema。                                                                                                                                                                                         | 使用 profile 属性 `cooldown` 指定，例如 `--profile kind=synchronous,cooldown=2` 表示冷却两秒，或 `--profile '{"kind":"concurrent","cooldown":{"mode":"duration","value":2}}`                                                              |
| --data-args 传递给数据集创建过程的参数 JSON 字符串。                                                                                                                                                                                                                                                                                                                                                                                     | 使用 data 属性 `load_kwargs` 指定，例如 `--data '{"kind":"huggingface","load_kwargs":{"split":"train"}}'`                                                                                                                                 |
| --data-column-mapper 应用于数据集的列映射 JSON 字符串。例如，'{"text_column": "article", "output_tokens_count_column" :"output_tokens"}'\`                                                                                                                                                                                                                                                                                               | 指定数据列映射器的 kind 和属性，例如 `--data-column-mapper '{"kind":"generative_column_mapper","column_mappings":{"text_column":"instruction"}}`                                                                                          |
| --data-finalizer 将数据集行转换为请求的 finalizer JSON 字符串。例如，'generative' 或 '{"type": "generative"}'\`                                                                                                                                                                                                                                                                                                                          | 指定 finalizer 的 kind，例如 `--data-finalizer kind=generative`                                                                                                                                                                           |
| --data-num-workers 用于数据加载的 worker 进程数。                                                                                                                                                                                                                                                                                                                                                                                        | 在 Data Loader 的 `num_workers` 属性中指定，例如 `--data-loader kind=pytorch,num_workers=3`                                                                                                                                               |
| --data-preprocessors-kwargs 传递给所有预处理器的参数 JSON 字符串。                                                                                                                                                                                                                                                                                                                                                                       | 为数据预处理器构造函数添加参数，例如 `--data-preprocessor '{"kind":"encode_media","audio_kwargs":{"format":"mp3"}}'`                                                                                                                      |
| --data-preprocessors 要应用于数据集的预处理器列表。例如，'encode_media,my_custom_preprocessor'                                                                                                                                                                                                                                                                                                                                           | 指定预处理器的 kind 和属性，例如 `--data-preprocessor kind=encode_media`；可以重复使用此选项来配置多个预处理器。                                                                                                                          |
| --data-sampler 数据采样器类型。                                                                                                                                                                                                                                                                                                                                                                                                          | shuffle 函数是数据加载器的属性，例如 `--data-loader kind=pytorch,shuffle=true`                                                                                                                                                            |
| --data-samples 数据集样本数。-1（默认值）表示使用所有样本，并动态生成更多样本。                                                                                                                                                                                                                                                                                                                                                          | 在 Data Loader 配置中指定，例如 `--data-loader kind=pytorch,samples=10`                                                                                                                                                                   |
| --data HuggingFace 数据集 ID、数据集路径、数据文件路径（csv/json/jsonl/txt）或合成数据配置（json/key=value）。                                                                                                                                                                                                                                                                                                                           | 指定数据集 kind 及其属性，例如 `--data kind=huggingface,source=<id>` `--data kind=csv_file,path=<file.csv>` `--data kind=synthetic_text,prompt_tokens=128,output_tokens=64`                                                               |
| --dataloader-kwargs 传递给 dataloader 构造函数的参数 JSON 字符串。                                                                                                                                                                                                                                                                                                                                                                       | 直接传递给 Data Loader，例如 `--data-loader kind=pytorch,shuffle=true,samples=100`                                                                                                                                                        |
| --detect-saturation 使用默认设置启用过饱和检测。                                                                                                                                                                                                                                                                                                                                                                                         | 指定 oversaturation 约束的 kind 和属性，例如 `--constraint kind=over_saturation`                                                                                                                                                          |
| --disable-console-interactive 禁用交互式控制台进度更新。                                                                                                                                                                                                                                                                                                                                                                                 | 保持不变：`--disable-console-interactive` 或 `--disable-progress`                                                                                                                                                                         |
| --disable-console 禁用控制台上的所有输出（更新、交互式进度、结果）。                                                                                                                                                                                                                                                                                                                                                                     | 保持不变：`--disable-console` 或 `--disable-console-outputs`                                                                                                                                                                              |
| --max-error-rate 停止基准测试前允许的最大错误率。                                                                                                                                                                                                                                                                                                                                                                                        | 指定最大错误率约束的 kind 和属性，例如 `--constraint kind=max_error_rate,rate=10`                                                                                                                                                         |
| --max-errors 停止基准测试前允许的最大错误数。                                                                                                                                                                                                                                                                                                                                                                                            | 指定最大错误数约束的 kind 和属性，例如 `--constraint kind=max_errors,count=10`                                                                                                                                                            |
| --max-global-error-rate 所有基准测试的最大总错误率。                                                                                                                                                                                                                                                                                                                                                                                     | 指定最大总错误率约束的 kind 和属性，例如 `--constraint kind=max_global_error_rate,rate=10,minimum=100`                                                                                                                                    |
| --max-requests 每个基准测试的最大请求数。如果为 None，则运行至达到 max_seconds 或数据耗尽。                                                                                                                                                                                                                                                                                                                                              | 指定最大请求数约束的 kind 和属性，例如 `--constraint kind=max_requests,count=1000`                                                                                                                                                        |
| --max-seconds 每个基准测试的最大秒数。如果为 None，则运行至达到 max_requests 或数据耗尽。                                                                                                                                                                                                                                                                                                                                                | 指定最大运行时长约束的 kind 和属性，例如 `--constraint kind=max_duration,seconds=60`                                                                                                                                                      |
| --model 要进行基准测试的模型 ID。如果未提供，则使用第一个可用模型。                                                                                                                                                                                                                                                                                                                                                                      | 在后端配置的 `model` 属性中指定，例如 `--backend kind=openai_http,model=gpt4`                                                                                                                                                             |
| --output-dir 或 –-output-path：保存文件输出类型的目录路径                                                                                                                                                                                                                                                                                                                                                                                | 在各个输出配置中指定路径，例如 `--output kind=json,path=/tmp/reports/benchmark.json`                                                                                                                                                      |
| --outputs 要创建的每种输出的 filename.ext，或要创建的输出文件类型别名（json、csv、html）；使用默认文件名（benchmark.[EXT]）                                                                                                                                                                                                                                                                                                              | 重复使用 `--output` 选项指定多种输出格式，例如 `--output kind=json,path=benchmark.json –output kind=csv,path=benchmark.csv`                                                                                                               |
| --over-saturation 启用过饱和检测。传入包含配置的 JSON dict（例如，'{"enabled": true, "min_seconds": 30}'）。默认值为 None（禁用）。                                                                                                                                                                                                                                                                                                      | 指定 oversaturation 约束的 kind 和属性，例如 `--constraint kind=over_saturation,mode=enforce,min_seconds=30`                                                                                                                              |
| --processor-args 传递给 processor 构造函数的参数 JSON 字符串。                                                                                                                                                                                                                                                                                                                                                                           | 直接与 tokenizer kind 一起指定选项，例如 `--tokenizer '{"kind":"huggingface_auto","load_kwargs":{"fast":true}}'`                                                                                                                          |
| --processor 用于 token 数量计算的 Processor 或 tokenizer。如果未提供，则从模型加载。                                                                                                                                                                                                                                                                                                                                                     | 默认使用后端 target 支持的第一个模型对应的默认 tokenizer。若要覆盖，请指定 tokenizer 的 kind 和属性，例如 `--tokenizer kind=huggingface_auto,model=gpt4`                                                                                  |
| --profile 基准测试 profile 类型。可选项：sweep、async、poisson、synchronous、throughput、concurrent、constant。                                                                                                                                                                                                                                                                                                                          | 指定要使用的基准测试 profile kind 和属性，例如 `--profile kind=sweep,sweep_size=10,warmup=1,cooldown=1`                                                                                                                                   |
| --rampup 请求速率逐步提升所需的时间，单位为秒。适用于 Throughput、Concurrent 和 Constant 策略                                                                                                                                                                                                                                                                                                                                            | 使用 profile 属性 `rampup_duration` 指定，例如 `--profile kind=constant,rate=10,rampup_duration=2`                                                                                                                                        |
| --random-seed 用于可复现结果的随机种子。                                                                                                                                                                                                                                                                                                                                                                                                 | 指定随机种子配置的 kind 和属性，例如 `--seed kind=static,value=42`                                                                                                                                                                        |
| --rate 要测试的基准测试速率。具体含义取决于 profile：sweep=基准测试数，concurrent=并发请求数，async/constant/poisson=每秒请求数。                                                                                                                                                                                                                                                                                                        | "Rate" 过去用于表示各种 profile 类型的主要配置，含义不一。请通过 `--profile` 或 `--override profile.<name>` 指定相应属性：async/constant/poisson → `rate`，concurrent → `streams`，sweep → `sweep_size`，throughput → `max_concurrency`。 |
| --request-format 请求使用的格式。可选项取决于后端。<br/><br/>对于 vLLM 后端：plain（不使用 chat template，仅追加文本）、default-template（使用 tokenizer 默认模板），或 vLLM 文档中介绍的文件路径/单行模板。默认值：default-template<br/><br/>对于 openai 后端：HTTP 端点路径（/v1/chat/completions、/v1/completions、/v1/audio/transcriptions、/v1/audio/translations）或别名（例如 chat_completions）；默认值为 /v1/chat/completions。 | 在后端配置中指定，例如 `--backend kind=openai_http,request_format=/v1/responses`                                                                                                                                                          |
| --sample-requests 每种状态要保存的样本请求数。None（默认值）会保存全部；建议值为 20。                                                                                                                                                                                                                                                                                                                                                    | 使用 metrics 配置的 `sample_size` 属性指定，例如 `--metrics kind=generative,sample_size=20`。如果未指定，默认保存所有样本。                                                                                                               |
| --scenario 内置场景名称或配置文件路径。CLI 选项会覆盖场景设置。                                                                                                                                                                                                                                                                                                                                                                          | 现在首选名称为 `--config`，但 `--scenario` 和 `-c` 仍是别名，例如 `--config chat` 或 `--config my-scenario.yaml`。                                                                                                                        |
| --target 后端目标 URL（例如，[http://localhost:8000](http://localhost:8000)）。                                                                                                                                                                                                                                                                                                                                                          | 在后端配置的 `target` 属性中指定，例如 `--backend kind=openai_http,target=http://localhost:8000`                                                                                                                                          |
| --warmup 预热设置：int、float，或以字符串形式提供的 dict（json 或 key=value）。用于指定测量开始前等待的时间或请求数。数值在 (0, 1) 之间时表示时长或请求数量的百分比。数值 >=1 时表示秒数或请求数。高级配置请参阅 TransientPhaseConfig schema。                                                                                                                                                                                           | 使用 profile 属性 `warmup` 指定，例如 `--profile kind=synchronous,warmup=2` 表示预热两秒，或 `--profile '{"kind":"concurrent","warmup":{"mode":"duration","value":2}}'`                                                                   |

| 为输出报告添加元数据                                                        | 指定键值对形式的元数据标签，这些标签将写入输出报告，例如 `--label gpu=NVIDIA_Z500 --label creator=Intrepid_Adventurer`                          |

## `guidellm benchmark from-file` → `guidellm export`（v0.7.2）

加载已保存的基准测试报告，并可选择重新导出数据。

在 **v0.7.2** 中，`guidellm benchmark from-file` 已替换为顶层 `guidellm export` 命令（`benchmark` 命令组已移除）。除此之外，其行为和选项与 v0.7.0/v0.7.1 的 `from-file` 命令相同。

| 选项                                                                                                                                         | 替代方式                                                                                                   |
| :------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------- |
| PATH 已保存的基准测试报告文件路径（默认值：./benchmarks.                                                                                     | 保持不变                                                                                                   |
| --output-path 保存重新导出的基准测试结果的目录或文件路径。如果是目录，所有输出格式都会保存到该目录。如果是文件，则匹配的格式会保存到该文件。 | 已移除：请改用 `--output`                                                                                  |
| --output-formats 基准测试结果的输出格式（例如，console、json、html、csv）。                                                                  | 改用 `--output` 指定 kind 和路径，例如 `--output kind=console` 或 `--output kind=json,path=benchmark.json` |

## `guidellm config`

显示配置设置

此命令已从 `guidellm config` 更名为 `guidellm env`，以明确它显示的是影响 GuideLLM 运行的环境变量。

之后，`guidellm config` 将用于其他用途：从 `run` 选项生成 YAML 配置文件。

## `guidellm preprocess dataset`

用于预处理基准测试所用数据集的工具。

| v0.6.0 选项                                                                                                                                                                                                                                                             | v0.7.1 对应写法                                                                                                                       |
| :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------ |
| data（位置参数）                                                                                                                                                                                                                                                        | 使用数据集描述符，例如 `kind=huggingface,source=<id>`                                                                                 |
| output_path（位置参数）                                                                                                                                                                                                                                                 | 结果文件路径，例如 `file.json`                                                                                                        |
| --processor TEXT 用于计算 token 数量的 Processor 或 tokenizer 名称。                                                                                                                                                                                                    | 指定 tokenizer 的 kind 和属性，例如 `--tokenizer kind=huggingface_auto,model=gpt2`                                                    |
| --config TEXT 以 JSON 字符串、key=value 对或文件路径（.json、.yaml、.yml、.config）形式提供的 PreprocessDatasetConfig。示例：`prompt_tokens=100,output_tokens=50,prefix_tokens_max=10` 或 `{"prompt_tokens": 100, "output_tokens": 50, "prefix_tokens_max": 10}` [必填] | 与短提示词处理 kind 一起合并到 `--strategy` 中，例如 `--strategy kind=ignore,prompt_tokens=100,output_tokens=50,prefix_tokens_max=10` |
| --processor-args TEXT 传递给 processor 构造函数的参数 JSON 字符串。                                                                                                                                                                                                     | 在 tokenizer 中指定选项，例如 `--tokenizer '{"kind":"huggingface_auto","model":"gpt2","load_kwargs":{"use_fast":false}}'`             |
| --data-args TEXT 传递给数据集创建过程的参数 JSON 字符串                                                                                                                                                                                                                 | 在位置参数数据描述符上使用 `load_kwargs` 指定，例如 `kind=huggingface,source=<id>,load_kwargs.split=train`                            |
| --data-column-mapper 应用于数据集的列映射 JSON 字符串                                                                                                                                                                                                                   | 指定数据列映射器对象，例如 `--data-column-mapper kind=generative_column_mapper,column_mappings.text_column=instruction`               |
| --short-prompt-strategy [ignore, concatenate, pad, error] 处理短于目标长度提示词的策略。[默认值：ignore]                                                                                                                                                                | 使用 `--strategy kind=ignore`（或 `concatenate`、`pad`、`error`）及 token 字段来选择                                                  |
| --pad-char TEXT 使用 "pad" 策略时用于填充短提示词的字符。                                                                                                                                                                                                               | 在 pad 策略中使用 `pad` 字段，例如 `--strategy kind=pad,prompt_tokens=512,output_tokens=256,pad=" "`                                  |
| --concat-delimiter TEXT 拼接短提示词时使用的分隔符（用于 'concatenate' 策略）。                                                                                                                                                                                         | 在 concatenate 策略中使用 `delimiter` 字段，例如 `--strategy kind=concatenate,prompt_tokens=512,output_tokens=256,delimiter="\n\n"`   |
| --include-prefix-in-token-count 计算提示词 token 数量时将前缀 token 计入其中。                                                                                                                                                                                          | 在 `--strategy` 中设置 `count_prefix=true`，例如 `--strategy kind=ignore,prompt_tokens=512,output_tokens=256,count_prefix=true`       |
| --push-to-hub 将处理后的数据集推送到 Hugging Face Hub。                                                                                                                                                                                                                 | 保持不变                                                                                                                              |
| --hub-dataset-id TEXT 上传所需的 Hugging Face Hub 数据集 ID（设置 `--push-to-hub` 时必需）。                                                                                                                                                                            | 保持不变                                                                                                                              |
| --random-seed INTEGER 用于可复现 token 采样的随机种子。[默认值：42]                                                                                                                                                                                                     | 指定随机种子配置的 kind 和属性，例如 `--seed kind=static,value=42`                                                                    |
