# Knee 프로파일과 적응형 동시 요청 수 조정

GuideLLM의 `knee` 프로파일은 동시 요청 수가 늘어나도 출력 처리량이 더 이상 크게 증가하지 않는 지점을 추정합니다. 이 전환 지점을 처리량의 Knee 지점이라고 합니다. 프로파일은 먼저 지정된 동시 요청 수에서 초기 측정을 수행하고 Knee 지점을 보고합니다. 필요에 따라 해당 지점 주변에 측정 지점을 추가하여 추정 결과를 더 정밀하게 구할 수 있습니다.

Knee 감지를 활성화하려면 `--profile`에 `kind=knee`와 함께 `initial_streams` 리스트를 지정하거나, `min_streams`, `max_streams`, `count`를 모두 지정하세요. 적응형 측정은 기본적으로 비활성화되어 있습니다.

## 기본 사용법

지정한 동시 요청 수에서 측정하고 Knee 지점을 보고하려면 다음과 같이 실행하세요:

```bash
guidellm run \
  --backend kind=openai_http,target=http://localhost:8000 \
  --profile '{"kind":"knee","initial_streams":[1,5,10,20,40,80,160]}' \
  --data kind=synthetic_text,prompt_tokens=1000,output_tokens=1000 \
  --constraint kind=max_duration,seconds=60 \
  --output kind=json,path=knee-benchmark.json
```

동시 요청 수를 달리하여 추가 측정을 자동으로 실행하려면 같은 프로파일에 적응형 옵션을 설정하세요:

```bash
--profile '{"kind":"knee","initial_streams":[1,5,10,20,40,80,160],"adaptive":true,"points_each_side":5,"max_step":3}'
```

대신 일정한 간격의 초기 측정 지점을 생성하려면 양 끝값을 포함한 범위와 지점 수를 지정하세요:

```bash
--profile '{"kind":"knee","min_streams":1,"max_streams":9,"count":5}'
```

이 예제는 동시 요청 수가 `1, 3, 5, 7, 9`인 지점에서 실행됩니다. 생성된 값은 가장 가까운 정수로 반올림하며, 정확히 중간에 있는 값은 올림합니다. 지정한 범위에는 요청한 수만큼 서로 다른 지점을 생성할 수 있을 정도로 충분한 정수가 있어야 합니다. 간격이 일정하지 않은 값을 직접 지정하려면 `initial_streams`를 사용하세요.

Knee 프로파일은 동시 실행 스케줄링 전략을 사용하며, 서로 다른 양의 정수로 이루어진 동시 요청 수를 5개 이상 오름차순으로 지정해야 합니다. Knee 지점을 추정하려면 측정을 완료하고 출력 처리량을 얻은 지점이 5개 이상 있어야 합니다. 처리량이 증가하는 구간과 정체되는 구간을 모두 포함하도록 범위를 선택하세요. 곡선이 평탄하거나 거의 직선이면 `status: no_knee`가 반환됩니다.

## 설정

| 옵션               | 기본값  | 설명                                                                  |
| ------------------ | ------- | --------------------------------------------------------------------- |
| `initial_streams`  | —       | 직접 지정할 초기 동시 요청 수. 최소 5개 이상을 오름차순으로 지정      |
| `min_streams`      | —       | 생성할 초기 동시 요청 수의 최솟값(해당 값 포함)                       |
| `max_streams`      | —       | 생성할 초기 동시 요청 수의 최댓값(해당 값 포함)                       |
| `count`            | —       | 생성할 측정 지점 수. 최소 5개                                         |
| `adaptive`         | `false` | 처음 추정한 포화 지점 주변에서 추가 측정 실행                         |
| `points_each_side` | `5`     | 적응형 측정 기준점의 아래쪽과 위쪽에서 각각 선택할 격자점 수의 최댓값 |
| `max_step`         | `5`     | 적응형 측정을 위한 동시 요청 수 격자에 적용할 최대 정수 간격          |

Knee 프로파일에는 `initial_streams`를 설정하거나, `min_streams`, `max_streams`, `count`를 모두 설정하세요. 두 방식 모두 하나의 벤치마크로 실행됩니다. `points_each_side`와 `max_step`은 양의 정수여야 합니다. 적응형 측정에서 사용하는 모든 동시 요청 수도 양의 정수입니다. GuideLLM은 적응형 측정을 시작하기 전에 이미 측정한 지점을 제외합니다. 일반적인 프로파일 시간 설정 옵션(`rampup_duration`, `warmup`, `cooldown`)은 두 단계에 모두 적용됩니다.

## Knee 지점 계산 방식

GuideLLM은 성공한 요청의 초당 출력 토큰 수를 처리량으로, 동시 요청 수를 부하로 사용합니다. 분석 과정은 다음과 같습니다:

1. 측정값을 동시 요청 수에 따라 정렬하고, 처리량이 없는 측정값은 제외합니다. 독립적인 피팅 함수는 동일한 동시 요청 수의 측정값을 평균하지만, Knee 프로파일에서는 측정 지점이 중복되면 포화 감지기의 판단이 모호해질 수 있으므로 서로 다른 동시 요청 수를 사용해야 합니다.
2. 동시 요청 수와 처리량을 비교 가능한 척도로 정규화합니다.
3. 전체 처리량 곡선에 하나의 직선을 피팅합니다.
4. 조건에 맞는 분할점을 시도하고, 각 분할점 이전의 상승 구간과 이후의 꼬리 구간에 각각 직선을 피팅합니다.
5. 상승 구간의 기울기가 양수이고, 꼬리 구간의 기울기가 상승 구간 기울기의 25% 이하이며, 두 직선을 사용한 피팅으로 제곱 오차가 50% 이상 줄어들고, 분할점의 처리량이 관측된 최댓값의 85% 이상일 때 해당 분할점을 채택합니다.
6. 채택된 피팅 결과 중 두 구간의 제곱 오차 합이 가장 작은 결과를 선택하고, 두 직선의 교점을 Knee 지점으로 보고합니다. 교점이 분할점의 바로 양옆에 있는 측정 지점 사이를 벗어나면 분할점 자체를 사용합니다.

동시 요청 수는 정수이지만, 피팅한 직선의 교점은 소수일 수 있습니다. GuideLLM은 `saturation_concurrency`(추정한 Knee 지점 이상의 측정값 중 가장 작은 정수 동시 요청 수)와 `breakpoint_concurrency`(최적의 구간별 피팅에 사용된 측정 지점)도 보고합니다.

## 적응형 측정

GuideLLM은 초기 벤치마크 결과를 분석한 뒤 적응형 측정 지점을 선택합니다. 처리량의 Knee 지점이 감지되면 추정한 값을 중심으로 추가 측정 지점을 선택합니다. 처리량의 Knee 지점이 없지만 과포화 감지기가 경계를 찾은 경우에는 마지막으로 안전한 동시 요청 수와 처음 과포화가 발생한 동시 요청 수의 중간값을 사용합니다. 경계 아래에 안전한 지점이 없으면 처음 과포화가 발생한 동시 요청 수를 사용합니다. 두 방법 모두 포화를 감지하지 못하거나 두 결과가 일치하지 않으면 적응형 측정을 건너뜁니다.

적응형 측정 격자는 요청한 아래쪽 지점들이 양수가 되도록 하는 범위에서 `max_step` 이하의 가장 큰 간격을 사용합니다. 중심값을 해당 간격의 가장 가까운 배수로 반올림하여 정수 기준점을 정하며, 정확히 중간에 있는 값은 올림합니다. 간격이 1이어도 모든 아래쪽 지점을 포함할 수 없으면 0 이하의 후보는 제외합니다. 기준점 자체도 후보에 포함되므로, 이미 측정한 지점을 제외하기 전에는 격자에 최대 `2 * points_each_side + 1`개의 지점이 포함됩니다.

예를 들어, 중심값이 `19.97`이고 `points_each_side=5`, `max_step=3`이면 기준점은 `21`이며, 후보 격자는 다음과 같습니다:

```text
6, 9, 12, 15, 18, 21, 24, 27, 30, 33, 36
```

더 촘촘한 격자를 사용하려면 `max_step=1`로 설정하세요. 중심값이 `19.97`이면 기준점은 `20`이 되고, 양쪽에 각각 5개 지점이 배치되어 후보 범위는 `15`부터 `25`까지가 됩니다.

초기 측정과 적응형 측정은 동일한 벤치마크 실행 과정을 따르며, 같은 백엔드, 데이터 로더, 프로파일 시간 설정 및 제약 조건을 사용합니다. 실행 시간 제한은 각 지점에 개별적으로 적용되므로, 지점이 추가되면 전체 실행 시간이 늘어납니다. 격자는 초기 동시 요청 수의 범위를 벗어날 수도 있습니다. `stopping_scope: all`인 제약 조건이 발동하면 어느 단계에서든 프로파일이 중단됩니다. 초기 Sweep 중에 발동하면 적응형 측정을 건너뛰고, 적응형 측정 중에 발동하면 나머지 예정된 지점을 실행하지 않습니다.

진행 상황 표시에는 초기 Sweep과 최대 `2 * points_each_side + 1`개의 적응형 측정 지점을 위한 공간이 확보됩니다. 지점이 제외되거나, 적응형 측정을 건너뛰거나, 중단 제약 조건이 발동하면 실제 측정 횟수가 이보다 적은 상태에서 프로파일이 종료될 수 있습니다.

추가 지점의 측정이 완료되면 GuideLLM은 초기 측정값과 적응형 측정값을 합쳐 최종 Knee 지점을 계산합니다. 적응형 측정 지점은 한 번만 선택하며, 최종 Knee 지점을 기준으로 다시 추가 측정을 시작하지는 않습니다. 적응형 측정이 비활성화되어 있거나 이를 건너뛴 경우에는 초기 측정값만 사용하여 최종 분석을 수행합니다.

## 과포화 감지 사용하기

처리량의 Knee 지점은 과포화 제약 조건 없이도 계산할 수 있습니다. 이 제약 조건을 추가하면 동시 요청 수와 첫 토큰 생성까지 걸리는 시간을 기반으로 시간에 따른 별도의 판단 근거를 얻을 수 있습니다. 초기 곡선을 측정할 때는 `mode=monitor`를 사용하면 나머지 측정 지점의 실행을 중단하지 않고 감지 메타데이터를 기록할 수 있습니다:

```bash
--constraint kind=over_saturation,mode=monitor,min_seconds=30
```

감지기의 모든 설정은 [과포화 시 중단](over_saturation_stopping.md) 문서를 참고하세요.

## 결과

콘솔 출력에는 최종 Knee 지점과 적응형 측정 상태가 요약되어 표시됩니다. JSON 및 YAML 보고서는 프로파일의 `conclusions` 리스트에서 `kind: knee_detection`인 항목에 전체 분석 결과를 저장합니다. 이 항목에는 다음 내용이 포함됩니다:

- `initial`: 설정한 동시 요청 수에서 수행한 Knee 및 과포화 분석 결과입니다.
- `adaptive_plan`: 중심값, 기준점, 간격, 후보 지점, 제외된 지점 및 추가로 측정할 예정인 지점입니다. 중단 제약 조건으로 인해 예정된 지점 중 일부는 실행되지 않을 수 있습니다.
- `final`: 초기 측정값과 적응형 측정값을 합쳐 분석한 결과입니다.

초기 측정값과 적응형 측정값은 보고서의 `benchmarks` 리스트에 함께 저장되며, 초기 측정값이 먼저 배치됩니다. 이 측정값을 통해 실제로 실행된 지점을 확인할 수 있습니다. 설정은 `config.spec.profile`에 저장되며, 각 벤치마크에도 해당 프로파일과 동시 실행 구성이 기록됩니다.
