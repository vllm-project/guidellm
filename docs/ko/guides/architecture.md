# 아키텍처

GuideLLM은 실제 추론 워크로드를 시뮬레이션하여 대규모 언어 모델(LLM) 배포 환경을 평가하고 최적화하도록 설계되었습니다. 모듈식 아키텍처를 통해 유연성과 확장성을 제공합니다. 아래에서는 핵심 구성 요소와 각 요소가 상호작용하는 방식을 설명합니다.

```
+------------------+       +------------------+       +------------------+
|   DatasetCreator | --->  |   RequestLoader  | --->  |     Scheduler    |
+------------------+       +------------------+       +------------------+
                                                    /         |          \
                                                   /          |           \
                                                  /           |            \
                                                 v            v             v
                                       +------------------+ +------------------+
                                       | RequestsWorker   | | RequestsWorker   |
                                       +------------------+ +------------------+
                                                 |                     |
                                                 v                     v
                                       +------------------+ +------------------+
                                       |     Backend      | |     Backend      |
                                       +------------------+ +------------------+
                                                 |                     |
                                                 v                     v
                                       +---------------------------------------+
                                       |         BenchmarkAggregator           |
                                       +---------------------------------------+
                                                 |
                                                 v
                                       +------------------+
                                       |    Benchmarker   |
                                       +------------------+
```

## 핵심 구성 요소

### 1. **Backend**

`Backend`는 생성형 AI 백엔드와 상호작용하기 위한 추상 인터페이스입니다. 요청을 처리하고 결과를 생성하는 역할을 합니다. GuideLLM은 vLLM과 같은 OpenAI 호환 HTTP 서버를 백엔드로 지원합니다.

- **역할:**
  - `RequestsWorker`에서 요청을 받습니다.
  - 텍스트 또는 채팅 완성 요청에 대한 응답을 생성합니다.
  - 백엔드가 준비되었는지 확인하고 사용 가능한 모델을 확인합니다.

### 2. **RequestLoader**

`RequestLoader`는 반복 가능한 객체에서 데이터를 가져와 백엔드로 보낼 요청을 생성합니다. 데이터가 올바른 형식을 갖추고 처리할 준비가 되도록 합니다.

- **역할:**
  - 데이터셋이나 합성 데이터 소스에서 데이터를 불러옵니다.
  - 백엔드와 호환되는 형식으로 요청을 생성합니다.

### 3. **DatasetCreator**

`DatasetCreator`는 데이터 소스를 불러와 Hugging Face(HF) 데이터셋 항목으로 변환합니다. 변환된 항목은 `RequestLoader`에서 스트리밍 방식으로 읽을 수 있습니다.

- **역할:**
  - 로컬 파일, Hugging Face 데이터셋 또는 합성 데이터에서 데이터셋을 불러옵니다.
  - 데이터를 `RequestLoader`와 호환되는 형식으로 변환합니다.

### 4. **Scheduler**

`Scheduler`는 백엔드로 보내는 요청의 스케줄링을 관리합니다. 멀티프로세싱, 멀티스레딩 및 asyncio를 함께 사용하여 오버헤드를 최소화하고 처리량을 최대화합니다.

- **역할:**
  - 백엔드로 보낼 요청을 스케줄링합니다.
  - 요청 큐와 결과 큐를 관리합니다.
  - 리소스를 효율적으로 활용합니다.

### 5. **RequestsWorker**

`RequestsWorker`는 큐에서 요청을 가져와 백엔드를 통해 처리하고, 결과를 스케줄러로 반환하는 작업 프로세스입니다.

- **역할:**
  - 스케줄러에서 받은 요청을 처리합니다.
  - 백엔드와 상호작용하여 결과를 생성합니다.
  - 결과를 스케줄러로 반환합니다.

### 6. **Benchmarker**

`Benchmarker`는 벤치마크마다 한 번씩 이루어지는 여러 `Scheduler` 호출을 묶어 관리합니다. `BenchmarkAggregator`를 사용하여 결과를 집계하고, 실행이 완료되면 결과를 `Benchmark` 객체로 정리합니다.

- **역할:**
  - 여러 벤치마크를 관리합니다.
  - 스케줄러에서 받은 결과를 집계합니다.
  - 결과를 최종 벤치마크 보고서로 정리합니다.

### 7. **BenchmarkAggregator**

`BenchmarkAggregator`는 벤치마크 결과를 저장하고 정리합니다.

- **역할:**
  - 여러 벤치마크의 결과를 집계합니다.
  - 결과를 `Benchmark` 객체로 정리합니다.
